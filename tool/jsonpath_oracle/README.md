# JSONPath oracle (host JVM)

The frozen `AnalyzeByJSonPath.kt` wraps **json-path 2.9.0**
(`gradle/libs.versions.toml:22`) directly — `JsonPath.parse(json).read(rule)` —
and hands the result to `getString`, which joins a list with `"\n"` and takes
`toString()` of anything else. `tool/jsonpath_probe/` already records what the
jar answers over a fixed document set (a transcript). This directory turns that
record into a **fixture**: a corpus, a golden produced from the frozen bytes, and
the product-side comparison in `test/jsonpath_differential_test.dart`.

Nothing in `AnalyzeByJSonPath.kt` except `@Keep` and the debug-print helper names
an Android type, and both are supplied here as the documented shim
(`FrozenDebugStub.kt`) or as the real annotation jar, so the frozen files are
compiled and executed as they are. `RuleAnalyzer.kt` — the splitter and
`{$.rule}` inner-rule pass `getString` runs first — is pure Kotlin.

This is **not** the four-stage device oracle. The frozen side of the contract is
a golden produced by the hash-pinned frozen APK on a device; here the frozen
bytes are executed in the host JVM instead, which is enough for a pure reader but
is recorded as a host-JVM source execution, not a device golden. The Android row
stays `not-run`; `evidence/jvm-host/manifest.json` states the same.

Files:

- `fixtures.json` — the corpus: four documents (the probe's three plus a
  rendering document), each rule, and the frozen form each row reaches. A row
  with a `declared` block is one the capability matrix already names.
- `JsonPathOracle.kt` — the harness: `getString` for the compared boundary and
  `ctx.read` recorded raw, each case run twice and refused when the two runs
  differ, so the golden says both what the frozen reader answers and whether the
  library refused the rule.
- `FrozenDebugStub.kt` — the frozen `Throwable.printOnDebug` (`LogUtils.kt:139`)
  is `if (BuildConfig.DEBUG) printStackTrace()`, and `BuildConfig` is generated by
  the Android build. The stub supplies the release behaviour: no output.
- `run_golden.sh` — resolves the Kotlin compiler, `kotlin-stdlib`,
  `kotlin-reflect` and Gson from the Gradle cache (no `kotlinc` is on `PATH`) and
  the five json-path jars from `tool/jsonpath_probe/`'s pin (`jars.sha256`,
  verified on every run), then compiles the two frozen files and runs the harness.
- `evidence/jvm-host/golden.json` and `manifest.json` — the result, its
  provenance, and the comparator's `notCompared` list by name.

Reproduce:

```
bash tool/jsonpath_oracle/run_golden.sh
```

## The compared boundary

`AnalyzeByJSonPath.getString(rule)` is the field text a JSON rule carries into
the stage output. The product's entry is `JsonSourceRules.extract(document,
rule)`. The corpus compares that pair, so it holds:

- the filter forms the used sources reach (`==`, `!=`, `<`, `<=`, `>`, `>=`,
  `in`, `nin`, `=~` with the `i` flag, `size`, `empty`, `exists`, the bare
  existence and bare boolean forms, `&&`/`||`/`!` inside a filter) over arrays and
  over the map a filter points at;
- the slice forms (`[a:b]`, `[:b]`, `[a:]`, negative ends, a third field, a window
  past the end, a reversed window) and the index forms (`[N]`, `[N, M]`, `[-N]`,
  `[*]`) as leaves of a rule and in the middle of one;
- the `\n` join over the matches, and the rendering of a match that is not a
  scalar: the object form `{k=v, k2=v2}` (`JSONObject.toString`), the array form
  `[a,b]` with quoted string elements (`JSONArray.toString`), the JSON object form
  `{"k":v}` a map takes *as an array element*, and the escaping `JSONValue.escape`
  writes. `render-*` rows pin all of it, including the empty containers, the
  nested forms, a quote, a backslash, a tab, a newline and non-ASCII text.

The failure *shape* of a refused rule is not compared (the contract compares
categories, not exception classes): the frozen reader swallows the library's
exception and leaves an empty text, and the product refuses by name.

## What this fixture does not cover

- The device golden (`not-run`, owned by #38).
- A number at or above 1e7 or below 1e-3: the JVM writes scientific notation
  where Dart writes a decimal. No row reaches that band.
- The rule-level `&&`/`||`/`%%` merges over more than one branch and the
  `{{...}}` template form; those stay the adapter's source-derived rows.
- `validate` and the pipeline above `extract`: this fixture compares the reader's
  field text, not the rule-shape gate or the stage that consumes the text.
